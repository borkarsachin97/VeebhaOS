1. CORE TESTING PHILOSOPHY: SIMULATOR-ONLY FIRST

- Principle of Silicon Isolation:
  Physical hardware (RDA8809) will NOT be touched during early OS development.
  Hardware flashing introduces slow flashing loops, SPI bus lockups, and blind
  crashes. All OS logic, templates, widgets, memory cleanup, and font shapers
  must pass 100% of simulator test gates first.

- The Simulator Board Profile (board_simulator.h):
  A dedicated virtual device profile mirroring the target feature phone:
  * Emulates the exact display resolution: 176x220 (portrait) by default[cite: 1].
  * Configurable compile-time resolution scaling (e.g., 240x320)[cite: 1].
  * Color format fixed to RGB565[cite: 1].
  * Fixed virtual memory budget: strictly limits LVGL pool to 2 MB to catch
    out-of-memory errors on the PC before they hit the 8 MB device RAM limit[cite: 1].
  * Maps PC input devices (Keyboard/Numpad) into physical phone keypad interrupts[cite: 1].
  * Virtual peripheral backends: mock battery level (0-100%), mock RTC clock,
    mock cellular signal strength, and host folder mounting for SD card storage.


2. THE 5-STAGE TESTING PIPELINE

STAGE 1: Unit & Component Testing (Headless / CLI)
- Target Modules:
  * T9 & Multi-Tap Parser: Test rapid keypresses, mode toggling (abc -> ABC -> 123),
    timeout character commitment (~800ms), and punctuation cycling[cite: 1].
  * Indic Text Shaper: Verify short 'i' matra reordering (U+093F) and conjunct
    ligature mapping into PUA indices[cite: 1].
  * Screen History Stack: Verify LIFO push/pop order, depth bounds checking,
    and row highlight index recovery[cite: 1].
- Pass Criteria: Clean execution with standard assertions (assert.h) without GUI.

STAGE 2: Interactive Desktop GUI Testing (SDL2 Window)
- Target Modules:
  * Display Abstraction Layer (DAL): 1:1 pixel preview at 176x220, double partial
    buffering (1/10th screen height), 60 FPS rendering[cite: 1].
  * Viewport Layout: Verify status bar (top 18px), content area (middle 184px),
    and softkey bar (bottom 20px) maintain exact boundary locks[cite: 1].
  * Keypad Navigation: Ensure D-pad Up/Down/Left/Right moves focus across list
    items, wrapping boundaries, and softkey action dispatchers[cite: 1].
  * Overlay Interrupts: Verify long-press on Call key drops the Quick Settings
    panel; long-press on '*' opens the Task Switcher[cite: 1].
- Pass Criteria: Full visual and interactive navigation using only the PC keyboard.

STAGE 3: Automated Framebuffer Snapshot & Visual Regression
- Mechanism:
  * Simulator supports headless execution flag: `./veebhaos_sim --snapshot`[cite: 1].
  * Automated script navigates through all 19 application screens and overlays[cite: 1].
  * Dumps raw screen buffers via `lv_snapshot_take()` to disk[cite: 1].
  * Python image comparison tool compares output against baseline golden images
    under `tests/snapshots/golden/`[cite: 1].
- Pass Criteria:
  * Zero pixel difference across English, Russian, and Hindi rendering tests.
  * Continuous shirorekha lines verified with zero broken horizontal pixels[cite: 1].

STAGE 4: Memory Profiling & Automated Keypad Fuzzing
- Memory Auditing:
  * Compile with AddressSanitizer (ASAN) and UndefinedBehaviorSanitizer (UBSan):
    `-fsanitize=address,undefined -g`
  * Run under Valgrind to catch heap memory leaks:
    `valgrind --leak-check=full --show-leak-kinds=all ./veebhaos_sim`
- Automated Keypad Fuzzer:
  * Built-in fuzzing task injects 50,000 randomized keypad events (D-pad moves,
    softkey clicks, rapid back button presses, menu entries)[cite: 1].
- Pass Criteria:
  * Zero memory leaks detected after opening and popping all 15 applications.
  * Zero heap fragmentation after 12-hour continuous fuzz run[cite: 1].
  * Operational RAM stays strictly within the 2 MB LVGL heap partition[cite: 1].

STAGE 5: Mock System Integration (Audio, Network & Storage)
- Mock Audio Pipeline:
  * Redirects VoC DSP playback calls to standard SDL2 audio output on Linux
    to verify playback states, track progress timers, and playlists[cite: 1].
- Mock File System:
  * Maps internal LittleFS Flash partition to `resources/mock_flash/`.
  * Maps external FatFS SD card to `resources/mock_sdcard/`[cite: 1].
- Mock Telephony & Networking:
  * Injects simulated incoming call events and incoming SMS text messages to
    verify background interruption handling, notification badges, and modals[cite: 1].
  * Bridges network socket calls to local Linux loopback for browser/radio stubs[cite: 1].
- Pass Criteria: All media and storage apps fully navigable without hardware dependencies.


3. HARDWARE HANDOFF CRITERIA (GATEWAY TO SILICON)

Real silicon flashing will ONLY begin when all the following conditions are met:
[ ] 1. All 5 declarative templates (List, Grid, Dialog, Editor, Media) render
       and navigate with zero coordinate hardcoding[cite: 1].
[ ] 2. 1-bit fonts (Terminus 12/14px, Gargi 16px) render with zero baseline jitter[cite: 1].
[ ] 3. 12-hour automated keypad fuzzing completes with 0 crashes and 0 memory leaks[cite: 1].
[ ] 4. All 19 application visual snapshot comparisons pass with 100% match[cite: 1].
[ ] 5. Binary compiled with MIPS cross-toolchain stays under the 4 MB Flash ceiling[cite: 1].
