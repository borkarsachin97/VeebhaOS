🧱 Phase 1: Board Configuration, Display Pipeline & Linux Desktop Simulator
--------------------------------------------------------------------------------
Establish board-level compile-time abstraction, dual-target build harness
(Linux SDL2 desktop simulator vs. bare-metal MIPS target), and graphics pipeline.

1. Dual-Target Development Environment (Linux SDL2 Simulator):
   - Native host compilation via GCC/Clang and CMake/Ninja on Linux desktop.
   - SDL2 window abstraction mapping directly to LVGL v9 display driver:
     * Real-time 1:1 pixel preview at target resolutions (176x220, 240x320)[cite: 1].
     * Virtual display rotation handling (0°, 90°, 180°, 270°) inside SDL2 window[cite: 1].
   - PC Keyboard to Phone Matrix Mapper:
     * Arrow Keys -> D-Pad (Up, Down, Left, Right)[cite: 1]
     * Enter / Space -> D-Pad Center / OK[cite: 1]
     * Left Alt / F1 -> Left Soft Key (LSK)[cite: 1]
     * Right Alt / F2 / Escape -> Right Soft Key (RSK)[cite: 1]
     * Numeric Keypad (0-9, *, #) -> Phone Alphanumeric Matrix[cite: 1]
     * 'C' Key -> Call Key (short-press / long-press)[cite: 1]
     * 'E' Key -> End / Power Key[cite: 1]
   - Instant sub-second compile-run cycle with full native GDB and Valgrind support,
     allowing rapid UI debugging without hardware flashing cycles.

2. Board Configuration Switchboard (src/board_config.h):
   - Modular device profiles selected at compile time (e.g., board_phoenix.h,
     board_mumba.h, board_simulator_sdl.h)[cite: 1].
   - Hardware presence macros: CONFIG_BOARD_2G (RDA8809), CONFIG_BOARD_LTE (CAT-1 SoCs),
     CONFIG_BOARD_SDCARD, CONFIG_BOARD_VOC, and peripheral clock gates[cite: 1].
   - Display dimension constants defined per board: CONFIG_DISP_HOR_RES (e.g., 176),
     CONFIG_DISP_VER_RES (e.g., 220), and color format (RGB565)[cite: 1].

3. LVGL v9 Core Port & Display Abstraction Layer (DAL):
   - Configure lv_conf.h with custom LV_MEM_SIZE of 2 MB from available 8 MB RAM[cite: 1].
   - Implement lv_display_create() with double display partial buffers sized to
     1/10th screen height to minimize RAM footprint and prevent tearing[cite: 1].
   - Hardware target: Bind flush callback to RDA GOUDA hardware blitter DMA engine.
   - Simulator target: Bind flush callback to SDL_UpdateTexture / SDL_RenderCopy.
   - Display driver interface supporting hardware-level rotation (0°, 90°, 180°, 270°)[cite: 1].

4. Design Tokens & Visual Theme:
   - High-contrast feature phone dark palette:
     * Background: Dark Charcoal / Pure Black (#121212 / #000000)[cite: 1]
     * Primary Accent: High-Contrast Cyan (#00E5FF)[cite: 1]
     * Secondary Accent: Amber (#FFC107)[cite: 1]
   - Support for high-contrast power-saving light/dark theme switching[cite: 1].

5. Phase 1 Milestone:
   - Clean compilation on Linux desktop SDL2 simulator and MIPS32 cross-toolchain[cite: 1].
   - Desktop simulator opens a pixel-perfect window and responds to PC keyboard
     events; hardware target boots to solid background and flushes test patterns[cite: 1].

🎮 Phase 2: Input Layer, 1-Bit Fonts & UI Template Engine
--------------------------------------------------------------------------------
Implement keypad mediation, 1-bit typography, and the zero-coordinate
declarative UI template engine so subsequent apps require zero manual layout math.

1. Input Abstraction Layer (IAL - src/hal/hal_input.c):
   - Map 12-key matrix keypad events: LSK, RSK, D-Pad (Up/Down/Left/Right/OK),
     Call, End/Power, 0-9, *, #[cite: 1].
   - Hardware/software debounce and timer-based press duration:
     * Short-press vs. Long-press detection[cite: 1].
     * Call key long-press -> Quick Settings Drawer[cite: 1].
     * Star (*) key long-press -> Multitasking Task Switcher[cite: 1].
   - Dedicated Idle Screen Shortcuts: D-Pad Up (Quick Settings), Down (Call Logs),
     Left (New SMS), Right (Media/Radio)[cite: 1].

2. T9 & Multi-Tap Character Engine (src/core/t9_engine.c):
   - Multi-tap character cycling for modes: abc, ABC, 123[cite: 1].
   - Hash (#) key cycles input modes, updating active visual tags[cite: 1].
   - Configurable character timeout timer (~800ms) for character commit.

3. 1-Bit Monochrome Typography Pipeline:
   - Latin & Cyrillic: Terminus 12px (status bar) and 14px (standard UI body)[cite: 1].
   - Devanagari (Hindi): Gargi 16px with 3-tier vertical metric layout (upper matra,
     shirorekha top line, base consonant, lower matra)[cite: 1].
   - Lightweight Indic shaping pre-processor for matra reordering (short 'i') and
     pre-rendered conjunct ligature resolution (ksha, tra, jnya, etc.)[cite: 1].
   - LVGL v9 font chaining via font->fallback linking Latin/Cyrillic to Devanagari[cite: 1].
   - Bitmaps stored in Flash .rodata.fonts for zero dynamic RAM overhead[cite: 1].

4. Zero-Coordinate UI Template Engine (src/core/ui_templates.c):
   - Screen Viewport Partitioning:
     * Status Bar: Fixed 18px top region (network bars, clock, battery icon)[cite: 1].
     * Content Viewport: Elastic middle area auto-filled via Flexbox or Grid.
     * Softkey Bar: Fixed 20px bottom region (dynamic LSK/RSK text and action dispatch)[cite: 1].
   - Standard Declarative Templates:
     * Template 1 (List View): Vertical flex column, auto-calculated row heights,
       center-locked scroll snapping, auto-registration to D-pad navigation group[cite: 1].
     * Template 2 (Grid View): Uniform 3x3 or 4x3 grid layout with 4-way D-pad wrapping[cite: 1].
     * Template 3 (Dialog/Alert): Modal card with background dimming and softkey hijack[cite: 1].
     * Template 4 (Editor): Text container wired directly to T9 multi-tap engine[cite: 1].
     * Template 5 (Media/Dashboard): Visual asset, track/caller headline, and progress slider[cite: 1].

5. Window & Lifecycle Navigation Stack (src/core/win_mgr.c):
   - LIFO execution stack (win_mgr_push_app, win_mgr_pop_app)[cite: 1].
   - Auto-destruction of popped screens with heap reclamation[cite: 1].
   - Position-memory tracking restoring D-pad focus to previous row indices upon pop[cite: 1].
   - Animated Boot Screen (src/ui/boot_screen.c): Phoenix branding, progress
     indicator, and auto-transition to Home[cite: 1].

6. Phase 2 Milestone:
   - D-pad and softkeys navigate between empty template views in the SDL2 simulator;
     multi-tap text entry and mixed English/Russian/Hindi labels render cleanly
     without manual coordinate code.

📦 Phase 5: Multi-Resolution Board Validation & App Loader
--------------------------------------------------------------------------------
Ensure display abstraction scales across targets and establish modular app loading.

1. Multi-Resolution Board Profile Verification:
   - Validate compile-time board targets:
     * Profile Phoenix: 176x220 portrait (RDA8809 2G)[cite: 1].
     * Profile Mumba: 240x320 QVGA portrait[cite: 1].
     * Profile Landscape: 320x240 / 220x176 landscape modes[cite: 1].
   - Verify instantaneous resolution switching in SDL2 simulator via build flags:
     e.g., `cmake -DBOARD_PROFILE=mumba .. && make run`
   - Verify that all declarative templates (List, Grid, Dialog, Editor) adapt
     proportions automatically using CONFIG_DISP_HOR_RES and CONFIG_DISP_VER_RES
     without layout code changes[cite: 1].

2. External App Loader Specification (src/core/app_loader.c):
   - Specify .vapp binary package format (magic header, target OS API version,
     entry symbol offset, requested heap budget)[cite: 1].
   - Execution Model for No-MMU Hardware:
     * Approach A (Native): Position-Independent Code (PIC / -mabicalls) ELF
       relocation loader resolving OS syscall symbols at load time.
     * Approach B (Sandboxed VM): Lightweight bytecode interpreter (e.g., WASM
       micro-runtime or Lua) executing safely within an isolated heap slice.
   - Enforce memory fences: Reject loading if .vapp allocation exceeds available
     free boundaries inside the 8 MB RAM limit[cite: 1].
   - Register .vapp MIME handler in the File Manager for one-click launching[cite: 1].

3. Phase 5 Milestone:
   - The same application codebase compiles and renders proportionally on both
     176x220 and 240x320 board profiles; external .vapp program executes
     successfully from SD storage[cite: 1].

🧪 Phase 6: Automated Verification, CI Pipeline & Profiling
--------------------------------------------------------------------------------
Enforce budget adherence, stability gates, and regression testing.

1. Headless Test & Snapshot Harness (src/main.c):
   - Command-line flag (--snapshot) running under the Linux SDL2 build without
     opening an interactive GUI window[cite: 1].
   - Automated script systematically visits all application screens, modals,
     and overlays, dumping raw framebuffers via lv_snapshot_take()[cite: 1].
   - Python pipeline converting raw frame dumps into reference PNGs under
     /app/screenshots/ (01_boot.png through 16_torch.png)[cite: 1].

2. Resource Budget & Memory Leak Auditing:
   - Enforce Flash ceiling: Total compiled OS binary must stay under 4 MB Flash
     (< 650 KB target for baseline build)[cite: 1].
   - Profile dynamic heap: Active operational RAM usage must remain within
     the 2 MB LVGL heap partition under full load[cite: 1].
   - Host Valgrind & ASAN analysis on Linux SDL2 simulator to catch buffer
     overruns and memory leaks before flashing silicon.
   - 12-Hour Automated Keypad Fuzzing: Scripted random D-pad, Call, and Softkey
     stress tests to verify zero memory leaks in the window navigation stack[cite: 1].

3. Phase 6 Milestone:
   - Green continuous integration run with automated snapshot diffing and
     zero heap leaks recorded across the 12-hour fuzz test[cite: 1].

🛠️ SYSTEM BOOT MODES & SPECIAL OPERATION STATES
================================================================================

1. Debug Log Mode:
   - Bypasses the graphical UI stack entirely during boot[cite: 1].
   - Spins up a background USB CDC / UART thread to stream real-time memory
     statistics (vPortGetHeapStats), register dumps, and vAppLog() trace calls[cite: 1].

2. Download & Recovery Mode:
   - Bare-metal recovery stub entered via hardware key combination at power-on[cite: 1].
   - Accepts, validates, and flashes incoming update binaries (veebhaos.bin)
     directly to SPI Flash via USB or serial link[cite: 1].

3. Super Battery Saving Mode:
   - Clock-gates non-critical peripheral blocks (Camera, FM, VoC when idle)[cite: 1].
   - Restricts display backlight to 10% via PMD current sink[cite: 1].
   - Suspends background multitasking queues[cite: 1].
   - Switches theme to high-contrast monochrome black (#000000) to cut display power[cite: 1].

4. Bluetooth PANU Tethering Link:
   - Bridges L2CAP / BNEP data channels into an lwIP network interface[cite: 1].
   - Allows network sockets (HTTP client, SNTP time sync, Internet Radio) to
     access the internet through a paired host phone or PC[cite: 1].
